## Overview

This exercise continues the Fiat-Shamir transcript construction by generating cryptographic challenges and computing the permutation polynomials needed to verify copy constraints in the PlonK protocol.

## What This Exercise Does

### 1. Generate Challenge β

The first challenge β is generated by hashing the current transcript (which contains public values and commitments from Exercise 19):

```python
beta = generate_challenge(transcript)
transcript = push(beta, transcript)
```

**Purpose of β:** Used in the permutation argument to randomize the position values, preventing the prover from adaptively choosing values that satisfy constraints without actually satisfying the copy constraints.

### 2. Generate Challenge γ

After β is added to the transcript, we generate γ from the updated transcript:

```python
gamma = generate_challenge(transcript)
transcript = push(gamma, transcript)
```

**Purpose of γ:** Provides additional randomization in the permutation check, ensuring the grand product argument is sound.

### 3. Compute Permutation Polynomials z, N, D

Using the challenges β and γ, we compute three polynomials that encode the permutation argument:

```python
z_poly, N_poly, D_poly = interpolate_z_N_D(a_blind, b_blind, c_blind, beta, gamma, Ω)
```

**The z polynomial:**
- Accumulator polynomial satisfying z(ω) = 1
- Recursive relation: z(ω^(i+1)) = z(ω^i) · [N(ω^i) / D(ω^i)]
- Encodes whether all copy constraints are satisfied

**The N polynomial (numerator):**
- At each point ω^i, N(ω^i) is the product of numerators across all three columns
- Numerator formula: pos(column, i) + β·f(ω^i) + γ
- Represents the "before permutation" side

**The D polynomial (denominator):**
- At each point ω^i, D(ω^i) is the product of denominators across all three columns
- Denominator formula: σ(pos(column, i)) + β·f(ω^i) + γ
- Represents the "after permutation" side

### 4. Commit to z Polynomial

Finally, we commit to the z polynomial and add it to the transcript:

```python
c_z = kzg.commit(z_poly)
transcript = push(c_z, transcript)
```

This commitment binds the prover to their permutation polynomial before the verifier issues more challenges.

## The Permutation Argument

### Why Permutations?

In a PlonK circuit, we need to enforce **copy constraints** - ensuring that the same value appears in multiple locations. For example:
- The output of gate 1 must equal the input of gate 2
- An initial value must be used in multiple gates

Rather than checking each equality individually, we use a **permutation argument** that proves all copy constraints at once using the grand product check.

### Grand Product Argument

The key insight is that if we have a permutation σ and values f, then:

```
∏(position + β·f(ω^i) + γ) / ∏(σ(position) + β·f(ω^i) + γ) = 1
```

if and only if all copy constraints are satisfied (all values in each equivalence class are equal).

### The z Polynomial Recursive Structure

Starting with z(ω) = 1, we build up the accumulator:

```
z(ω^1) = 1
z(ω^2) = z(ω^1) · N(ω^1)/D(ω^1)
z(ω^3) = z(ω^2) · N(ω^2)/D(ω^2)
z(ω^4) = z(ω^3) · N(ω^3)/D(ω^3)
```

If all copy constraints hold, then z(ω^5) should cycle back to z(ω^1) = 1.

## Verification Checks

The solution verifies two key properties:

### 1. Boundary Constraint: z(ω) = 1

We check that ZH divides L1·(z - 1), which ensures z(ω) = 1:

```python
ZH.divides(L1*(z_poly - 1))  # Should be True
```

- L1 is the Lagrange basis polynomial for the first domain point
- L1(ω) = 1 and L1(ω^i) = 0 for i ≠ 1
- So L1·(z - 1) = 0 at all domain points if z(ω) = 1

### 2. Recursive Constraint

We check that ZH divides z·N - D·z(x·ω), which ensures the recursive relation holds:

```python
ZH.divides(z_poly*N_poly - D_poly*z_poly(x*ω))  # Should be True
```

This verifies that at each domain point ω^i:
```
z(ω^i) · N(ω^i) = D(ω^i) · z(ω^(i+1))
```

Which is equivalent to:
```
z(ω^(i+1)) = z(ω^i) · N(ω^i)/D(ω^i)
```

## Key Concepts

- **Fiat-Shamir Transform:** Deriving challenges from transcript hashes
- **Permutation Argument:** Efficient checking of copy constraints
- **Grand Product Argument:** Using products to verify permutations
- **Challenge Generation:** SHA256 hash of transcript modulo prime
- **Accumulator Polynomial:** Recursive structure encoding constraint satisfaction
- **Blinded Polynomials:** Using witness commitments from Exercise 18/19
- **Transcript Ordering:** Challenges must be generated in specific order to prevent adaptive attacks
